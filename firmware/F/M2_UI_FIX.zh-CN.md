# Fujifilm AIR2-P8-M2 UI 修复

[English](M2_UI_FIX.md)

开发者：Caimankekw。新增代码采用 AGPL-3.0-only。本文描述离线机器码回归，不能代替实机启动、显示或射频测试。

## 修复内容

1. **TTL 的 DEF 页使用 AIR1 时，相对数字现在能在原定时器到期后清除。** F A5 原厂 `0x8618..0x8622` 只允许 MAN 进入 A6 定时器检查，导致原 M1 在 `0x8636` 接入的清屏处理无法被 TTL DEF 调用。M2 在 `0x8618` 加入有初始化、型号对象及模式检查的入口，仅额外放行 TTL + DEF + AIR1。MAN、TTL ABC 和 AIR2 沿用各自原行为。期限仍由原厂按键活动路径设置，`0x8FBE/0x78E0` 检查，没有新增平行计时器。
2. **选择 ALL 后，当页三个选框全部显示。** F 原厂 `0x880E` 只处理单行 1/2/3，selector 7 会清除全部选框。M2 在该 helper 后补上 F 本机 `LCD87` 的三个选框位 `0x02 | 0x08 | 0x20`。单行和 ABC/DEF 标签仍使用 F 原有布局；不改相机 ABC 开关或发射指令。
3. **AIR1 到期时仍有待发送事务，不再丢失清屏重试。** 原厂 `0x78E0` 到期后会将 A6 置为 `0xFFFF`，而 `0x863A..0x8640` 收尾会清零 A6。M1 在共享核心因 pending 事务拒绝清屏时仍执行收尾，导致数字继续保留而没有有效期限。M2 将 `0x8636` 改成 GOTO 入口；AIR1 返回未清屏时保留 `0xFFFF` 到期锁存，空闲后再次清屏，再执行原收尾。共享核心在清屏前重新采样原生编辑和发射准入；相机、队列或已检查的待处理中断忙时也走该重试分支。AIR2 仍常驻显示并正常消耗原期限，不会因为无需清屏而无限重试。

## 验证

在源码根目录运行 `python -X utf8 -B F/test_ui_parity_m2.py --out <结果.json>`。开发工作区对应根目录是 `analysis/air_remote_ttl_multi_air2`。测试通过正式生产 linker 在内存构建机器码，不运行安装器。

共 102 项，普通 Python 与 `-O` 均通过：

| 范围 | 数量 |
|---|---:|
| 从原始按键、功率入口进入，随后执行 `0x8618` 的 TTL/MAN × AIR1/AIR2 × ABC/DEF × 单行/ALL 期限路径 | 32 |
| 从 `0x742E` 原生显示入口执行相同组合的真实 LCD 位检查 | 32 |
| AIR1 pending 到期 → 排空 → 重试清屏，含 15-bit tick 回绕 | 6 |
| AIR2 pending 时仍正常完成原期限收尾 | 2 |
| 旧 idle 快照后置原生相机/队列/IRQ 忙门，确认不重绘并在解除后重试 | 27 |
| 未初始化时保留原厂模式 gate 的回退 | 2 |
| 所有原厂字节修改均限制在声明的 AIR2 hook 与新增代码段内 | 1 |

另有原有 F 整合测试 7 项通过。测试逐次核对 `0xFE/0x2B1/0x1DA/0x1E0` ISR 状态未被 idle 路径覆盖；到期处理不修改绝对功率、TTL 补偿、灯组开关或已发送报文。使用显式 MMIO、NVM 控制器与下游发送队列消费模型，不宣称测得物理时间、真实 RF 完成或实际 LCD 可视效果。

JSON 结果由脚本生成；开发工作区记录在 `m2_verification/ui_parity_results.json` 和 `m2_verification/ui_parity_results_optimized.json`，源码归档不要求附带这些历史生成文件。共享核心后续整合可能改变完整镜像哈希，因此封包时必须在最终镜像上再次运行此脚本。未修改原厂 HSS，未修改 Canon 固件和旧 M1 发布包；最终资格字段由整合流程统一更新。
