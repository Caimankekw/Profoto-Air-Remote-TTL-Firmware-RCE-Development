# Air Remote TTL-S A6 的 AIR2-P8 移植

开发者：Caimankekw。新增代码采用 AGPL-3.0-only；原厂固件及逆向资料的权利归原权利人。

这是 Sony A6 独立适配层，连接共享的六组 AIR2-P8 核心。原 Canon 固件的 HSS 修改没有引入本版本，Sony 原有相机协议、HSS、射频消费与调度程序保持原码。当前目录是构建源码及离线验证资料，不代表已经验证真机启动。

## 功能与实现

- 保留 TTL、MAN/AIR1、MAN/AIR2；AIR2 显示三组绝对功率，每次调节发送完整六组目标快照。
- C＋MODEL 切换 AIR1/AIR2，C＋HEAD 切换 ABC/DEF；A、B 与加减键不加入组合键等待。
- ALL 作用于六组；TTL 的 ABC 使用曝光补偿，DEF 使用记忆的手动子模式。
- AIR1 数值遵循原空闲期限消失，AIR2 三组绝对数值常驻；DEF 不改变原相机协议中 ABC 组的意义。
- 使用独立双页日志保存模式、AIR2 六组功率、闪光/造型灯状态及页面。保留原厂设置日志与频道保存逻辑。

## 源码结构

`native_backend.py` 连接原状态、原 LCD 格式化器、六组显示及原队列；`native_hooks.py` 连接正常界面的启动、前台服务、按键、调功和显示边界。`port_profile.json` 记录各地址及硬件能力证据。共享核心和日志实现位于 `../shared/`。

`radio/fast_empty_queue.py` 只在原队列为空且相机/射频软件状态允许时提交一个 17 字节记录；短临界区重新检查条件，完整提交后由原调度程序继续发送。成功仅表示入队，不表示灯具执行确认。原中断清队列仍有最终决定权。

持久化在按键全部释放且软件状态稳定空闲后执行，每次擦写前重新检查条件。Flash 操作会暂时停顿 CPU，短提交也有有限中断延迟；“保留原 HSS”指不替换原 HSS 算法及发送流程，并非宣称新增功能没有任何时序开销。还需真机确认启动、按键、六组控制、掉电记忆及相机 TTL/HSS。

## 证据与范围

状态 RAM 采用共享审计支持的 `0x680..0x7FF`，适用原对象与索引合法的运行条件；不是所有损坏状态的形式化证明。两页日志为 `0xF800` / `0xFC00`，原日志 `0x1F800..0x1FBFF` 不变。目标族能力来自原固件寄存器签名、设备定义和数据手册交叉核对，尚未通过实机读出确认精确芯片型号。

各组件测试区分实际执行的原指令与显式模拟边界。最终发布还需对同一链接映像进行完整验证，不能仅凭 `port_profile.json` 中的工程证据标记直接发布。
