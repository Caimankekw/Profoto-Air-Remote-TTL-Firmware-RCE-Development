# Sony A6 原生发帧接口复核

这是离线移植依据，不是可刷固件。所有地址为 PIC18 程序**字节地址**，候选明文以 `0x4000` 为基址。没有运行更新器、访问 USB 或变更原厂文件。

## 已确认的链路

`普通 M 调功 0x7490 → 0x9516 构造帧 → 0xA158 入队 → 0x5C08 调度 → 0x5DA4 加 RSGT1 → 原 0x028D 对象状态机`

| 地址 | 参数、结果与证据 |
|---|---|
| `0x7490` | W 为组号；RAM `0x09B` 为有符号步进 `+1/-1/+10/-10`，映射命令 `06/07/0D/0E`。RAM `0x0D8 != 0` 时原函数直接返回。`0x6066..606C` 是普通调用处。 |
| `0x9516` | W 为帧首字节；`0x078/079` 为 12 字节负载指针。帧组装于 `0x07B..08A`：首字节、`FF FF FF`、12 字节负载。`0x452C` 的 `FFFFFF` 经 `0x798C` 转为三字节。最后置 `0x076=0x7B` 跳 `0xA158`。不会自动加 `0x20`。 |
| `0xA158` | `0x076` 为 **bank 0** 内 16 字节帧的起始低地址；W 返回队列接受 `1` 或拒绝 `0`。先调用 `0x8F84` 检查空间，写一个零标记，再追加16字节。不是灯端 ACK。 |
| `0x00E6..00EB` | RAM 队列描述符：写索引、读索引、使用量、容量、数据指针低/高。初始化 `0x668A..669C` 确认容量100、数据区 `0x0400..0463`。 |
| `0x8F84` | 16 字节帧仅当原使用量 `<=83` 时接受，包含额外一字节记录标记。`>=84` 返回0。 |
| `0x6F7A / 0x7296` | 原队列写一个字节/读一个字节；指针传于 `0x06B/06C`。读取为空返回0，不能把0作为空队列唯一判断。 |
| `0x5DA4` | `0x07A/07B` 为发送对象/缓冲指针；原调用使用 `0x0143`。零记录类型转成 `RSGT1 + frame16`，长度21存 `0x0144`，文本/帧从 `0x014A` 开始。 |
| `0xAF70` | 原 A6 实际是 `RETLW 0x02`，**不是读取对象字段**。因此 `0x7FDC` 选择 `RSGT1`，`0xA2DE` 返回16。保留这些函数。 |

`0xA158` 经过实际原指令重放会改动调用暂存 `0x06B..077`、FSR、W/STATUS/BSR及队列；不得复用 Canon 的寄存器或 bank2 常驻状态。`0x9516` 还使用 `0x07A..08A`。准确整合需父工程已确认的 Sony RAM 布局与调用现场。

## AIR2 接入建议

保留原 HSS、相机时序、UART 和发送状态机。仅在新增 AIR2 UI 已提交目标值后构造以下完整 16 字节帧。`0xA158` 已用于证明帧合同，但后续并发审计发现 ISR 共队列竞态，实际整合应使用下述短提交候选：

```
27 FF FF FF 01 11 A B C D E F HEAD6 MODEL6 00 00
```

A..F 是 0.1 功率单位，范围1..100，必须有完整目标，不能猜测0或FF为“不改变”。这个绝对帧来自已开发 P8/接收端合同，不是本次发现的 Sony 原厂功能。Sony 原传输层能无修改透传它已完成指令级验证；无线模块与灯具实际接受仍须产品测试。

原相对帧是：`group FF FF FF 01 command group 00 00 00 00 00 00 00 00 00`。组1..6和ALL7通过帧层；不能据此声称原UI已支持D–F。

提交返回0时保留当前域的 dirty 目标并稍后再试；不要重复叠加相对命令。原相机中断在接受后清队列属于原厂 abort，不能因此无条件重发旧域快照。新状态和帧暂存不能占原 `0x0400..0463` 队列区。`0xA158` 本身不屏蔽中断，且 ISR 可达的 `0xAC84` 写入同一队列；`audit_concurrency.py` 已复现记录串接和截断，故仅做状态预检仍不够。

## 验证与边界

运行 `python -B analysis/air_remote_ttl_multi_air2/S/radio/verify_native_queue.py`：308 例指令重放通过，其中272例为真实原指令，覆盖组1..7、8种普通命令、AIR2快照、环形队列起点0/92/99，以及使用量0..100；另36例执行新增高RAM桥接函数及原队列函数。未 stub 掉队列或序列化函数。共享 VM 补充了 POSTDEC 间接寄存器和 DECF/INCF Carry 语义；这里的修正不编辑旧 VM。

`native_queue_adapter.py` 提供不含hook的 PIC18 callable wrapper，frame RAM 和代码地址由整合者显式分配。它检查原 `0x0D8`，调用 `0x8F84` 容量预检与 `0xAB66` 记录标记，再通过 `0x86EA` 的 `0x071/072` 16位源指针追加16字节，避开 `0xA158` 的bank0帧约束。离线测试覆盖源地址 `0500/06F8/0EE0`、D8=0/1/255、count=0/83/84/100；保持源帧和D8不变。不分配永久RAM、不改变原HSS代码、不屏蔽中断；整合者仍须核对调用时机与并发边界。

原D8门控证据：`0xA5A4` 检查并置D8=1，随后 `0xA906` 清队列、`0x90BA` 加入 `RSUU1\r`；`0x93BC` 清D8并加入 `RSUU0\r`。`0xA814` 调用上述进入函数并设置 `0x1C2/1C3` deadline；`0xA586` 到期调用退出函数，随后原 `0x5C08` 服务。这是原独占radio模式门控，尚不能等同所有相机忙状态的完整证明。

`protocol_adapter.py` 是纯主机报文合同，不能直接刷入。`native_queue_verification.json` 为结果。`abi_preimages.json` 固定输入哈希及接口首字节，供父工程拒绝错误固件。

## 短提交候选与并发验证

`fast_empty_queue.py` 的 `construct(base, frame_ram, irq_ram)` 生成242字节 callable，仅在原队列为空、原D8独占关闭且已观察相机软件状态允许时提交。它二次检查后用固定 MOVFF 写入17字节，最后发布count，逐位恢复原GIEH/GIEL；不修改IPEN或确认任何pending中断。调用必须位于前台、原queue服务函数之外。`native_queue_adapter.py` 保留作ABI研究，不是实际提交建议。

`test_fast_empty_queue.py` 使用共享PIC18 VM通过2555例，包括740个指令边界的原生产者交错；最长临界区74指令周期。`static_isr_audit.py` 确认原ISR直接闭包可达生产者、不可达原消费函数，未发现间接控制点。详见 [并发审计](CONCURRENCY.zh-CN.md)。软件quiet检查不等于物理HSS完成；最后一次pending检查之后到达的相机事件仍可能被有限延后。

尚未确认完整无线模块 ACK 语义或实际空口时延；上述测试不证明物理HSS时序。原机 `0x5C08` 及 `0x028D` 状态机仍承担发送/超时/重试，不能以队列返回1冒充无线发射成功。
