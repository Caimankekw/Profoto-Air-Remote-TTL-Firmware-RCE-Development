# Nikon C5 AIR2 移植记录

这里是离线逆向和适配证据，尚不是可刷写固件。所有地址均为 PIC18 字节地址。原厂更新器从未执行，本轮未访问 USB。

## 已闭合的容器和执行架构

- 输入为 `air_remote_ttl/air-remote-ttl-n-firmware-c5-win/Air-Remote-TTL-N-Firmware-C5.exe`，SHA-256：`4fa0d7c1ae8201910e0586eef30feadb9230e3c30c7b67b8dc4c2d344dea5591`。
- 原厂 HEX 资源 `AirTTLB1Updater.Resources.RMRTN_firmware.hex` 在 EXE 的文件偏移 `2125208`，长度 `312708`，稀疏范围 `[4000,1FC10)`、`[1FFF0,20000)`。
- C11 地址变换表可以恢复 `[4002,10000)`。共享解包脚本还核对了原编码高尾与 C11 已确认 FF 尾相同。这里只保留首两字节未知，不把占位值当作指令。
- `4050` 的小端头 CRC 为 `F4B9`，等于 `crc16_linear(4002..404F + 4052..40FF)`，**没有 C11 的 XOR 0B15**。
- 代码入口 `4100`，初始化 `56DE`，正常主循环 `4CF6..4D42`，非 FF 原内容结束于 `AA80`。

Nikon C5 采用按键对象、函数指针、异步发射队列架构。它不是 C11 的固定偏移版。P8 的高 RAM `200/260/280/330/340` 在 Nikon 原程序中都有正常用途，必须重新分配。

## 按键、模式和显示

`4D44` 采集全部输入，`8E62` 将每个键的布尔输入移入七位历史并保留 bit7。`9BA6` 每次消费一个键，地址为 `0272 + 4 * index`，index 在 `0..10` 循环。`4ECC` 是单对象事件机；不是 C11 单键优先扫描器。

| index | 对象 RAM | 动作 | 已确认的原入口 |
|---:|---:|---|---:|
| 0 | 0272 | MODE | 7B88 |
| 1 | 0276 | CHANNEL | 82A6 |
| 2 | 027A | A | 946E，W=1 |
| 3 | 027E | B | 946E，W=2 |
| 4 | 0282 | C | 946E，W=3 |
| 5 | 0286 | MODEL | RAM63..65 函数指针 |
| 6 | 028A | HEAD | RAM66..68 函数指针 |
| 7 | 028E | + | 7E0A，释放 +1，长按 +10 |
| 8 | 0292 | − | 7E0A，释放 −1，长按 −10 |
| 9 | 0296 | TEST | A3EC → A1BE |
| 10 | 029A | PORTE.1 的额外输入 | 需保持原行为，尚不命名物理键 |

按下由 `7DB0` 分派，普通界面进入 `55EC`。释放由 `7F18 → 8630` 分派；长按由 `9BCA → 6786` 分派。最后三次采样全 1/全 0 对应按下/释放候选；持续按下会检查七位历史和原计时器。原阈值 250、650 为内部计数，不宣称毫秒。

模式对象指针是 `RAM49:4A`，正常基址 `01B1`；`model[0] = 0` 为 TTL，`1` 为 MAN。`model[4..6]` 是 ABC TTL 补偿，`model[8]` 是频道。`RAM60` 选择组 1、2、3 或 ALL=7。MAN 的临时相对值为 `99/9A/9B`，Head 掩码 `4C`，Model 掩码 `50`。

原 LCD 缓冲为 `88..92`，三个数值行从 `89/8B/8D` 开始。`6F44` 是带正负号的十分位格式化：`11=88`、`12=行地址`、`13=有符号十分位`。`9D76` 写单个数码；`9BEE` 经 `8BCA/97EC/9F0E` 发送 LCD 数据。AIR2 需要自己的绝对值和符号处理，不能直接让原相对值超范围充当绝对功率。

## 无线适配边界

原 `9D54` 可以排入普通 16 字节报文：`RAM18` 是低 256 字节内的源指针。原缓冲 `1D..2C` 可在明确的 UI 调用边界暂借，不能直接把高 RAM 地址塞进八位参数。

原发送队列描述符为 `93..98`，缓冲 `0400..0463`，容量 100。原接收队列使用 `01CA` 描述符和 `0300` 缓冲。已有原指令回放确认：发送队列数量不超过 83 时接收 17 字节（普通标记 0 加 16 字节）；数量达到 84 时返回失败且不修改队列。回放的 AIR2 `cmd11` 由 `5E34` 原传输构造器产生逐字节一致的 `RSGT1` 加 16 字节输出，命令本身未被原状态机解释或改写。

适配层应保存调用点仍活跃的低 RAM、FSR、W、STATUS、BSR，构造 16 字节快照、调用原队列，仅在成功后清除 dirty。不要直接写 UART 或在等待 UART 时屏蔽中断。`RAM4B` 是原特殊无线状态阻塞标记，不是 TTL/MAN 模式。

## 保留原 HSS 的实现方向

保留原相机 ISR、热靴同步、HSS 状态机、RSGT1/UART 调度和通道配置。新增策略只接管用户 AIR2/分页状态、用户按键对应设置报文及 LCD 覆盖。

`C + HEAD`、`C + MODEL` 应依据原独立按键对象做有限仲裁，且必须同时处理按下、释放、长按三个事件入口，避免组合成功后又触发关灯或选组。`+/-` 原事件不进入等待窗口。共享六组策略由 `shared/runtime_generator.py` 提供，本型号只提供原生接口包装，避免复制出四套不同策略。

具体地址与原始入口前像见 `candidate_port_map.json`。后续已实现 `native_backend.py`、`native_hooks.py` 和 `port_profile.json`，并完成有限原指令回放。最新双语说明、NV资格与时间基准见 `N_TIMING_AND_NATIVE_ABI.zh-en.md`；最终完整集成与封包资格仍由公共构建流程判定，不据此声称真机启动或无线互通。
