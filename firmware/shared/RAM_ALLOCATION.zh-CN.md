# F / N / O / S 私有 RAM 分配核查

本轮结论：**支持将 `0x680..0x7FF` 的 384 字节用于当前四型号的离线私有 RAM 布局。** 依据是原固定对象、初始化范围、已核查的合法索引/长度、通用函数的实际用途，以及候选芯片共有的物理 RAM 能力；没有发现正常控制流下与该区重叠的原生对象。这是有边界的工程分配结论，不是所有错误状态下的形式化证明，也没有进行实机刷写验证。

审计读取 `shared/stock/{F,N,O,S}/original.base4000.partial.bin`、已知字节掩码及各型号候选反汇编；只生成本说明和 [ram_allocation_audit.json](ram_allocation_audit.json)。未修改原厂镜像、公共 VM、其他成员代码，未运行更新器或访问 USB。

## 已确认的固定分配

下表使用包含末端的 RAM 地址。ROM 初始化复制及清零循环已按原始指令复核；它们不是对整个运行期占用的上界证明。

| 型号 | 启动初始化入口 | 初始化覆盖的最高 RAM 字节 | 启动中较高区间 |
|---|---:|---:|---|
| F A5 | `5F6E` | `67F` | 清 `600..67F`、`500..5B7`、`400..4B1`；复制 `300..386`、`267..2B8`、`1CF..1F7` |
| N C5 | `56DE` | `5B6` | 清 `500..5B6`、`400..463`、`300..363`；复制 `364..3B3`、`200..271`、`1E4..1F7` |
| O A4 | `69CA` | `363` | 清 `300..363`、`200..26E`、`100..1CD`；复制 `26F..2C2`、`1F1..1F9` |
| S A6 | `6174` | `463` | 清 `400..463`、`3BB..3EC`、`200..2A3`；复制 `300..3BA`、`1F3..1FB` |

原厂运行期还有不在启动清零末端表内的局部对象，不能复用。例如 S 的 `2A4:2A5` 是当前按键对象指针，`2A6` 是标志，`2A7..2B1` 是显示复制缓冲；O 的 `2C3`、`2C4..2CE` 也有显示用途。这些地址虽然仍低于候选区，足以说明“启动没有清零”不等于空闲。

## 全范围固定引用检查

对四份已知原始程序的 `[4002,10000)` 每一个偶地址检查两字指令模式，包含可能的数据及第二指令字；并非只检查线性 listing 认为的指令边界。

- 没有 `MOVFF` 源或目标落入 `[680,C00)`。
- 没有 `LFSR` 立即数落入 `[680,C00)`。
- `MOVLB` 常数集合：F=`0,1,2,4,E,F`；N=`0,1,3,E,F`；O/S=`0,1,2,E,F`。没有 bank 6、7、8、9、A、B 的显式选择。
- 原厂启动不会初始化拟分配区；新组件必须自行初始化，不得依赖上电 SRAM 值。

这种检查能排除固定引用，**不能排除经变量、索引、自动递增或间接写 BSR 得到的地址**。例如 F 仍然能通过 `LFSR0=600` 使用 bank 6，即使没有 `MOVLB 6`。

## 动态指针：尚未闭合的具体入口

JSON 保存全部非零 `LFSR`、FSR 高字节的 `MOVFF` 重载、其他显式高字节修改，以及自动增减间接寄存器操作。它们是逐指令清单，不是假定运行时值。特别是 startup 的 FSR1 有时仅作为复制长度计数，不能把每个 `LFSR` 立即数都解释成缓冲区地址。

| 型号 | `MOVFF → FSR高字节` 数量 | 特别需要约束的通用 RAM 读入口 | 原码中的直接调用点 |
|---|---:|---:|---|
| F | 62 | `8E06` | `804C,893E,8D1E,8DF0` |
| N | 68 | `74B4` | `748C,80EC,853E,8D9C` |
| O | 65 | `8B9E` | `7BB4,8330,86C0,8B8A` |
| S | 61 | `889E` | `7A98,83DE,8720,8888,8974,924A` |

上述通用函数将 `TBLPTRL/H` 复制至 `FSR1L/H`，然后读取 `INDF1`。这里 TBLPTR 被用作 RAM 指针暂存；不能因为名字叫 TBLPTR 就把其值限制为 ROM 表地址。需要继续对调用者的实参来源、长度、索引和自动递增次数做约束。

其他 FSR2 重载来自原生对象/参数字段。源字段自身低于候选区，不代表它存放的指针也低于候选区。本轮没有将每一种运行状态符号执行到构造点，因此不会写“所有间接访问最高止于 67F”。以下进一步检查用于判断正常模型能否进行工程分配。

## 通用入口与正常对象的进一步核查

上述入口不是内存分配器。它们的上层分别是定长字符串复制、按长度复制、按长度追加到串行发送队列，以及读取到 NUL 的字符串长度函数。四型号的对应入口及所有直接上层调用点已写入 JSON；Sony 另有使用中断 scratch 的字符串长度和串行追加副本。

- F：`8018` 的目标是 `176`、长度 10，或 `DE`、长度 3；后者在 `73E4` 明确清 `E0` 再读取字符串。`8914` 的已核查调用包括 `87→2D8` 的 11 字节 LCD 快照、目标 `C1` 且最大 6 字节（`688A..689C` 限幅）、目标 `C4` 的 12 字节复制，以及 `43D2/43D8` 原厂前缀的 5 字节复制。串口来源包括固定 flash 字符串 `43C6/43CC` 和原低 RAM 格式缓冲 `DA`。
- N：最高的大对象从 `4CCE` 传入基址 `500`；`487A` 的偏移 `AA`、长度 `0D` 到达 `5B6`，没有跨入新区。其他初始化、成员字段和字符串缓冲也位于原静态区。
- O：`6774..6786` 构造描述符 `95`，缓冲为 `300`、容量 100；LCD 快照为 `8A→2C4` 的 11 字节。已审核中断闭包的接收缓冲 `215..246` 与工作区 `247..26E` 均位于低区。
- S：`668A..669C` 构造描述符 `E6`，缓冲 `400`、容量 100。原追加器 `6F7A/7002` 在满容量时拒绝，写索引达到容量后回绕，因此正确初始化及合法生产/消费状态下数据范围为 `400..463`。中断字符串路径的来源是 `7D9E` 的 `025` 格式缓冲、`980C` 的 `024` 格式缓冲及 `A5A4` 的 flash `453A` 常量；并非外部传入的任意 RAM 地址。

最接近新区的 F `600..67F` 已单独检查。`600E..6018` 确实清零 128 字节，但本轮没有恢复其运行期对象名称/构造。所有显式 `MOVLW 06`、较大 `LFSR`、ROM 初始化表已检查；`B19E/B220` 返回的 `0600` 用作热靴时序标量，`63C4` 一组 `00/06` 等字段用作位偏移/长度，不能误认作 `600` 指针。目前没有发现从这个区跨到 `680` 的实际访问。仍保留整个 `600..67F`，不会将用途尚未命名的原区分配给新组件。

这些结果支持在**原静态对象及合法长度/索引不被破坏**的前提下使用新区。没有发现 heap 或以 FSR 为软件栈扩展至该区的初始化结构；不把这个观察扩大成任意损坏状态下不存在越界的保证。

## 栈与中断

四版可见的动态回调使用 `PUSH` 配合 `TOSL/TOSH/TOSU`，属于硬件返回栈操作；本轮未发现初始化 FSR 为软件帧栈的证据。这不能替代调用深度分析，也不能证明所有 FSR 自增都不是别的长期缓冲。

原始中断入口 `4108` 的 FSR 保存位置：

- F：`FSR1` 保存至 `1B:1C`，`FSR2` 至 `1D:1E`，入口/出口可见成对保存恢复。
- N：分别为 `09:0A`、`0B:0C`。
- O：分别为 `1A:1B`、`1C:1D`。
- S：分别为 `61:62`、`63:64`，并保存 `PROD`、`TBLPTR`、`TABLAT` 至 `65..6A`。

这些保存区没有直接覆盖候选区。中断调用的接收、队列、缓冲函数仍必须检查间接别名；不能用中断入口的保存地址代替整个中断闭包。新 core 调用原生函数时应遵循各型号的寄存器/FSR/BSR 合同，不可假定所有型号与 Canon 一致。

## 分配建议与验收边界

当前选择 `[680,800)` 共 384 字节。器件能力核查见 [identity_report.json](identity_report.json)：独立匹配到的 PIC18F/LF46/47J13/J53 候选全部将此区以及 `800..BFF` 映射为通用 RAM。128 KiB 配置布局与原日志地址进一步支持 47 系列目标，但没有读取实体芯片 ID。使用共同能力即可满足本次布局，不需要强行指定某一芯片型号。

1. 保留原模型对象及合法索引/长度，不将本报告的有限审计写成完整动态路径证明。遇到新增可达对象或实际 RAM 追踪重叠时必须重新审核分配。
2. 最终组件测试覆盖原生接收/发送、按键、显示、相机模式、设置保存、中断、休眠/唤醒等受改动影响的路径。原厂自身的共享状态也必须遵循相应 ABI；例如 F 中断会写 `FE`，不能将 `B0..FF` 全当作可任意备份恢复的 scratch。
3. 新区全部由新启动代码显式初始化；传给原生 helper 的指针必须符合它的完整地址宽度与长度合同。尤其不可使用只保留低八位的旧 copy helper 访问新区域。
4. 对最终链接镜像启用 RAM 读写追踪，区分“原生函数访问新区”和“新 core 正常访问新区”。实际机器码测试覆盖以上边界和中断交错；测试通过属于有限覆盖证据，不应写成穷尽证明。

`[800,C00)` 有共同物理能力证据，本次没有使用它的必要；不扩大当前 384 字节合同。硬件能力、原程序正常对象范围、最终链接组件的 RAM 写入集合是不同层面的证据，应分别保留。
